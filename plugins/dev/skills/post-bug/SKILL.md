在每次任務週期後分析執行結果中的改進空間，並據此優化後續策略。
將關鍵問題、原因分析、解決方法與預防策略整理為結構化錯誤筆記。

## 執行方式：委派 Sub-agent 背景撰寫

**撰寫筆記的工作必須全部委派給 sub-agent 背景執行**，不得由主 agent 親自寫入，以避免阻塞主 agent 與使用者的後續對話。

步驟：

1. 主 agent 從對話中整理出以下資訊（純文字摘要即可，不需讀任何檔案）：
   - 今日日期（`YYYY-MM-DD`）
   - 錯誤類型（可多個：typo / knowledge-gap / architecture-defect / requirement-misunderstanding / race-condition / technical-debt）
   - 問題描述、錯誤原因、解決方法、避免方法
   - 使用者意圖（為什麼要這樣改、想避免什麼）
   - 相關檔案路徑（若有）

2. 主 agent 呼叫 `Agent` tool，參數設定：
   - `run_in_background: true`
   - `model: "haiku"`
   - `prompt`：將上述所有資訊以**完整自包含**的文字傳入，並附上本 SKILL.md 的完整撰寫規範（TL;DR 格式、index.md 更新規則等），讓 sub-agent 不需對話 context 也能獨立完成任務。

3. 主 agent 啟動 sub-agent 後**立即回到與使用者的對話**，無須等待結果。

> Sub-agent 會在背景完成：建立資料夾 → 寫筆記（含 TL;DR）→ 更新 index.md（僅新增列，不覆寫）。

## 使用者意圖（與「怎麼修」同等重要）

僅記錄「bug 是什麼、怎麼改」不足以讓下次開發對齊使用者的目標。**必須從對話中推敲並寫下：使用者為什麼希望換寫法、想防什麼、想優化什麼**（一句話到一小段即可，勿空泛）。

撰寫時可對照下列常見動機（可多選），並用**使用者自己的用語**摘要若對話裡有出現：

| 意圖類型 | 例句／線索 |
|----------|------------|
| **可靠性／正確性** | 失敗要中止不要靜默繼續、不要誤判資料狀態 |
| **規模／資源** | 資料變大會 OOM、要分批、要 iterator、不要一次撈滿 |
| **API／職責清晰** | 兩步合成一步、介面不易用錯、函式語意與「完成」定義要一致 |
| **維運／可解讀** | log 欄位不要誤導 on-call、告警要講得出故事 |
| **一致性／技術債** | 與 spec 對齊、命名與現行行為一致 |

**落點：** 每則相關筆記正文建議含獨立小節 **`## 使用者為何希望這樣改（意圖）`**；若與 TL;DR 重複，可在 TL;DR 用一行 **意圖：** 濃縮，正文再展開。

這樣下次遇到「類似功能」（例如又一個 Redis 全量讀、又一個結算步驟）時，agent 會先聯想**使用者的取捨**，而不只抄技術形狀。

---

1. 粗心疏忽 (typo) - Typo、忘記 edge case、copy-paste 錯誤
2. 知識缺口 (knowledge gap) - 不了解 API/框架行為、語言特性
3. 架構缺陷 (architecture defect) - 設計不良、職責不清、耦合過緊
4. 需求誤解 (requirement misunderstanding) - 對需求理解有誤、邊界條件不清
5. 競態條件 (race condition) - 併發、時序問題、race condition
6. 遺留技術債 (technical debt) - 舊程式碼問題、過時依賴

錯誤筆記放置於**專案內**的 `.claude/docs/learning-notes` 資料夾中（若不存在則建立）。每天一個日期資料夾，每種錯誤類型一個檔案（結構見下方）。同日同類型的檔案已存在時，在檔尾以 `---` 分隔追加新一則，不得覆寫。

每則筆記**必須在開頭加上 TL;DR 區塊**（用 `<tl;dr>...</tl;dr>` 標籤包住），方便 agent 在筆記變多時只讀濃縮重點、不載入全文，以節省 context：

- **何時要想起這則：** 什麼情境/檔案/功能要聯想到這則。
- **不要做：** 2～4 條具體反例。
- **要做：** 2～4 條正確做法。
- **意圖（建議）：** 主人想避免的風險或想達成的產品／維運目標（一句話）。
- **自問（可選）：** 一兩句檢查清單。

TL;DR 區塊後再寫完整內容，建議順序：

1. **`## 使用者為何希望這樣改（意圖）`**（若此則源自主人的重構／改寫要求，**勿略**）
2. 問題描述、錯誤原因、解決方法、避免方法等

資料夾結構如以下：

```
.claude/docs/learning-notes/
├── 2026-02-02/
│   ├── typo.md
│   ├── knowledge-gap.md
│   ├── architecture-defect.md
│   ├── requirement-misunderstanding.md
│   ├── race-condition.md
│   └── technical-debt.md
├── 2026-02-03/
│   ├── knowledge-gap.md
│   ├── architecture-defect.md
│   ├── requirement-misunderstanding.md
│   ├── race-condition.md
│   └── technical-debt.md
└── index.md # 索引文件，用於分類並列出所有錯誤筆記，快速查詢
```

## 更新 index.md（禁止整份覆寫）

- **變更前必須**讀取現有 `index.md` 全文。
- **只**在對應分類表格中**新增一列**（或修正該則既有列）；**不得**用「初始範本」或空白表**整檔覆寫**，否則其他日期的索引列會全部消失。
- 僅當 `index.md` **不存在**時，才用上方〈index.md 初始範本〉建立新檔。
- 若懷疑索引與磁碟上 `YYYY-MM-DD/*.md` 不一致，可掃描資料夾後**補列遺漏**，仍須保留原有表格列。
